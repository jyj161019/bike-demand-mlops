# 1. 서비스 목적, 데이터, 모델

## 서비스

| 항목 | 내용 |
|---|---|
| 서비스 | 날씨와 날짜를 넣으면 그 시간대의 서울 공공자전거 대여 대수를 예측하는 API |
| 사용자 | 자전거 재배치·정비 인력 배치 계획을 세우는 운영 담당자 |
| 목적 | 수요가 많은 시간대에 자전거가 부족하지 않도록 미리 준비 |
| 입력 | 날짜, 시(0~23), 기온(°C), 습도(%), 풍속(m/s), 강수량(mm), 적설(cm), 공휴일 여부 |
| 출력 | 예측 대여 대수 (대/시간, 0 이상 정수), 모델 버전, 요청 ID |

## 데이터

- 출처, 라이선스: [data/raw/README.md](../data/raw/README.md)
- 기간: 2017-12-01 ~ 2018-11-30, 1시간 단위 8,760건
- 정답: `Rented Bike Count` (시간당 대여 대수)

### 처리 기준

| 처리 | 이유 |
|---|---|
| `Functioning Day = No` 행 제외 | 운영하지 않은 날이라 정답이 항상 0. 수요가 아니라 운영 여부를 학습하게 됨 |
| 시정, 이슬점, 일사량 열 사용 안 함 | 사용자가 예측 시점에 알기 어려운 값 |
| 계절 열 사용 안 함 | 월에서 계산 가능해 중복 |
| 날짜 → 월, 요일, 주말 여부로 변환 | 요일·계절 패턴 반영 |
| 열 이름이 아니라 위치로 매핑 | `°C` 등 특수문자가 인코딩에 따라 깨짐 |

결측치, 중복(날짜+시 기준), 제외된 행 수는 학습할 때 `models/<버전>/metadata.json` 의 `data_check` 에 자동 기록됩니다.

### 정답이 입력에 섞이지 않도록 한 점

- 입력에 대여 대수와 관련된 값(전날 대여량, 이동평균 등)을 넣지 않았습니다.
- 학습/평가 자료를 **무작위가 아니라 날짜 기준**으로 나눴습니다. 무작위로 나누면 같은 날의 앞뒤 시간이 학습과 평가에 동시에 들어가 성능이 실제보다 좋게 나옵니다.

### 분리 기준

| 구분 | 기간 | 용도 |
|---|---|---|
| 학습 | 2017-12-01 ~ 2018-08-31 | 모델 학습, 기준 방법 계산 |
| 평가 | 2018-09-01 ~ 2018-11-30 | 성능 측정 (학습에 사용 안 함) |

## 모델

| 항목 | 내용 |
|---|---|
| 모델 | scikit-learn `HistGradientBoostingRegressor` (직접 학습) |
| 손실 | poisson (대여 대수는 0 이상의 개수) |
| 설정 | `src/train.py` 의 `MODEL_PARAMS`, random_state=42 |
| 기준 방법 | 학습 기간의 (시간대 × 주말 여부)별 평균 대여량 |
| 버전 | `models/<버전>/metadata.json`: 버전 이름, Git 커밋, 데이터 해시, 라이브러리 버전 |
